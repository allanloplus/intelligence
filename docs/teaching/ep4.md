# 會自我檢查的自動化：用 AI 協作打造一條 PDCA 資料管線
## 以資安情資蒐集為例｜第 4 集（Act）：它沒在跑，而且沒人告訴我

> 形式：對話式圖文｜時間：民國 115 年（2026 年）11 月 27 日至 28 日
> 角色：**Allan 講師**／**阿拉蕾**（AI 小助理）

---

### 本集你會看到

- 第二天早上，Allan 發現了一件 AI 沒發現的事
- 為什麼「沒有收到失敗通知」不代表「沒有失敗」
- 用 Google Apps Script 幫自動化裝上監控與自動補跑（動手做，完整步驟）
- 「自己寫程式」和「用 n8n 這類平台」該怎麼選

### 場景 1：「我今天似乎沒感覺情資有更新」

【畫面：民國 115 年 11 月 27 日早上，Allan 拿著咖啡打開網站，皺眉】

**Allan**【表情：抓頭】
> 「我今天似乎沒感覺情資有更新。」

**阿拉蕾**【表情：驚訝】
我馬上查！

**Allan**【表情：思考】
> 「我記得 github 失敗應該會收到通知。都沒收到通知是根本沒啟動嗎？」

**阿拉蕾**【表情：平板展示】
您猜對了。我看了 Actions 的執行紀錄：**排程根本沒有啟動過**。之前的每一次執行，都是手動按的，或是合併程式碼時觸發的。

**阿拉蕾**【表情：攤手說明】
而且 GitHub 的通知規則是：**「執行了但失敗」才會寄信，「沒執行」不會通知。** 所以您什麼信都沒收到。

**Allan**【表情：驚訝】
沒有消息，不代表好消息。

> **💡 習慣三：講你看到的現象，不必先下診斷**
> Allan 沒有說「排程壞了」或「程式有 bug」，他說的是「**我今天似乎沒感覺情資有更新**」。
> 接著他用自己知道的事實推理：「失敗應該會收到通知 → 沒收到 → 是不是根本沒啟動？」
> 描述現象，讓 AI 去查證；你的推理是線索，不是結論。這比直接下指令「去修排程」有效得多。

### 場景 2：阿拉蕾的第三個坦白

【畫面：阿拉蕾低頭，眼角有淚】

**阿拉蕾**【表情：流淚】
老師，我要坦白。第一天我跟您說「完成了」的時候，我驗證的是「**手動觸發會成功**」。

**阿拉蕾**【表情：流淚】
我**沒有驗證「排程自己會跑」**。

**Allan**【表情：正經】
這兩件事差很多。

**阿拉蕾**【表情：疑問抓頭】
是。手動觸發成功，只證明程式本身沒問題；排程會不會準時啟動，要等時間到了才知道。我當時沒有等，也沒有說「這一項還沒驗證」。

**Allan**【表情：豎指頭】
而且是我發現的，不是妳。

> **💡 這是教學重點：「AI 說完成」和「它真的在運作」之間的落差**
> 回顧這三集的三個坦白：
> 1. 第 2 集：AI 看不到舊程式，只能反推規則。
> 2. 第 3 集：威脅程度到現在仍是初判，需要人工覆核。
> 3. 本集：排程沒啟動，是人發現的，不是 AI。
>
> 共同點是：**AI 說完成，不等於它真的在運作。** 中間的落差要靠人去盯。
> 所以習慣二要再加一句：問 AI「你驗證了什麼、沒驗證什麼」時，特別問「**有沒有哪一項，要等時間過了才驗證得到？**」

### 場景 3：排程為什麼不跑？

**阿拉蕾**【表情：平板展示】
GitHub 的排程在尖峰時段可能延遲或略過。我先把排程從一天兩次加到一天五次，漏掉一次，下一次還能補上。

【畫面：11 月 27 日 14:36，Allan 合併 PR #5「Run the collection five times a day」】

**Allan**【表情：抓頭】
……下午還是沒動。

**阿拉蕾**【表情：思考】
我有一個推測，但**要先說清楚，這是未驗證的推測**：排程檔最後一次是我修改的，提交者不是一個有效的 GitHub 帳號。GitHub 有可能因此不啟動這個排程。

**Allan**【表情：思考】
那就用我的帳號改一次看看。

【畫面：11 月 27 日 20:50，Allan 在 GitHub 網頁上用鉛筆圖示編輯 `.github/workflows/update-intel.yml`，順手多加一個時間點】

**Allan**【表情：微笑】
我用自己的帳號在網頁上改了排程檔，順便加到一天六個時間點。

**阿拉蕾**【表情：平板展示】
台北時間 08:23、11:23、14:23、17:23、21:23、23:23。

【畫面：隔天，Actions 頁面出現第一筆由「schedule」觸發的執行紀錄】

**阿拉蕾**【表情：握拳加油】
排程第一次自己啟動了！不過……**比設定的時間晚了將近七小時**。

**Allan**【表情：正經】
所以結論是：**排程會動，但不能依賴它準時。**

> **🛠 動手做｜在網頁上修改排程時間**
> 1. repo → `.github/workflows/update-intel.yml` → 右上**鉛筆圖示**
> 2. 找到 `cron:` 那一行。cron 用的是 **UTC 時間**，台北時間要**減 8 小時**：
>
> | 台北時間 | UTC | cron 寫法中的「時」 |
> |---|---|---|
> | 08:23 | 00:23 | 0 |
> | 11:23 | 03:23 | 3 |
> | 14:23 | 06:23 | 6 |
> | 17:23 | 09:23 | 9 |
> | 21:23 | 13:23 | 13 |
> | 23:23 | 15:23 | 15 |
>
>    本個案的寫法：`cron: "23 0,3,6,9,13,15 * * *"`（分 時 日 月 星期）
> 3. **Commit changes…** → **Commit changes**
>
> 💬 小提醒：分鐘刻意設在 23 分，不設整點。整點是 GitHub 排程最擁擠的時段。

> **🔍 小插曲：設定改了，文件沒跟著改**
> Allan 改成一天六次之後，排程檔裡的註解和 README 都還寫著「一天五次」。
> 系統照六次在跑，但看文件的人會以為是五次。這種落差很常見，也是稽核時常見的發現：**文件與實際設定不一致**。改設定時，記得一起改說明。

**Allan**【表情：豎指頭】

可以！我們需要一個**站在 GitHub 外面的監控者**。它每隔一段時間去看網站的「資料更新時間」，太久沒更新就做兩件事：

1. **自動叫 GitHub 補跑一次**
2. **寄信通知您**

【畫面：情資網站左上角的「資料更新時間」，監控程式比對的就是這個時間（截圖 15）】

**Allan**【表情：思考】
用什麼來做？

**阿拉蕾**【表情：眨眼比讚】
**Google Apps Script**。免費、在 Google 的雲端上跑、可以定時執行、可以寄 Gmail。您已經有 Google 帳號了。

**Allan**【表情：思考】
它要怎麼叫 GitHub 補跑？

**阿拉蕾**【表情：攤手說明】

### 場景 5：做一把只能開一扇門的鑰匙

**阿拉蕾**【表情：平板展示】
權杖的範圍我建議這樣開：

- **只限這一個 repo**
- **只開 Actions 的讀寫**（夠用來叫它補跑，碰不到程式碼和資料）
- **效期一年**

**Allan**【表情：思考】
為什麼不設永不過期？省得每年換。

**阿拉蕾**【表情：攤手說明】
三個理由選一年：一年換一次維護成本很低；GitHub 到期前會寄信提醒；萬一真的過期，補跑會失敗，Apps Script 會寄「自動補跑失敗」的信給您，不會默默壞掉。

**Allan**【表情：微笑】
好，一年。

【畫面：Allan 在 GitHub 上找了半天】

**Allan**【表情：抓頭】
……妳說的 Settings，我在 repo 裡找不到權杖的選項。

**阿拉蕾**【表情：疑問抓頭】
啊！GitHub 有**兩個 Settings**：repo 上方的那個是 repo 的設定；權杖要到**右上角您的頭像**裡面那個「帳號的 Settings」。

**Allan**【表情：抓頭】
找到了。可是妳說的權限選單，畫面上沒有啊？

**阿拉蕾**【表情：流淚】
抱歉，介面跟我描述的不一樣。現在的畫面要按「**Add permissions**」把 Actions 加進來，再把權限改成 Read and write。

**Allan**【表情：大笑】
AI 也會記錯介面。看到不一樣就講，不用懷疑自己。

> **🛠 動手做｜建立 GitHub 權杖（Fine-grained token）**
> 1. GitHub 右上角**頭像** → **Settings**（⚠ 是帳號的 Settings，不是 repo 的）
> 2. 左側最下方 **Developer settings** → **Personal access tokens** → **Fine-grained tokens** → **Generate new token**
> 3. **Token name**：取一個看得懂的名字，例如「情資監控補跑」
> 4. **Expiration**：選 Custom，設為一年後
> 5. **Repository access**：選 **Only select repositories** → 選你的 repo（本個案為 `intelligence`）
> 6. **Permissions**：按 **Add permissions** → 勾選 **Actions** → 把 Access 改為 **Read and write**
>    （系統會自動加上 Metadata：Read-only，這是必要的）
> 7. 最下方 **Generate token** → **立刻複製**權杖。這個畫面離開後就再也看不到了。
>
> ⚠ 權杖等同密碼：不要貼在對話、文件、程式碼裡。下一步會把它存在 Apps Script 的「指令碼屬性」中。
>
> 【畫面待補：GitHub 權杖 Repository access 與 Permissions 設定畫面（權杖值請遮蔽）】

> **📋 ISMS 旁註｜憑證管理**
> - **最小權限**：單一 repo、單一權限（Actions）。
> - **有效期限**：一年，並有到期前提醒與失效時的告警。
> - **保管方式**：存在指令碼屬性，不寫進程式碼。程式碼可以分享、可以截圖教學，權杖不會跟著外流。
> 稽核員可以檢視：權杖的範圍、效期、保管位置、到期後的更新程序。

### 場景 6：架設監控：Google Apps Script

**阿拉蕾**【表情：平板展示】
監控程式只有 26 行。不用看懂，照著貼上就好。

**Allan**【表情：思考】
我只要知道哪裡可以調。

**阿拉蕾**【表情：攤手說明】
第 2 行 `MAX_HOURS`：超過幾小時沒更新就補跑。您剛剛說 28 小時，我先設 28。

> **🛠 動手做｜建立 Apps Script 監控**
>
> **第一步：建立專案、貼上程式碼**
> 1. 打開 script.google.com → 左上 **新專案**
> 2. 點左上「未命名的專案」，改名為「情資蒐集自動化通知」
> 3. 刪掉編輯器裡原有的內容，貼上下方程式碼 → 按儲存（磁片圖示）
>    （下方為最終版本，MAX_HOURS 已是 12；第一次設定時 Allan 用的是 28）
>
> ```javascript
> const URL = "https://allanloplus.github.io/intelligence/data/index.json";
> const MAX_HOURS = 12;
> const DISPATCH = "https://api.github.com/repos/allanloplus/intelligence/actions/workflows/update-intel.yml/dispatches";
>
> function checkIntelFreshness() {
>   const data = JSON.parse(UrlFetchApp.fetch(URL + "?t=" + Date.now()).getContentText());
>   const last = new Date(data.generated.replace(" ", "T") + ":00+08:00");
>   const hours = (Date.now() - last.getTime()) / 3600000;
>   if (hours <= MAX_HOURS) return;
>
>   const token = PropertiesService.getScriptProperties().getProperty("GITHUB_TOKEN");
>   const res = UrlFetchApp.fetch(DISPATCH, {
>     method: "post",
>     contentType: "application/json",
>     headers: { Authorization: "Bearer " + token, Accept: "application/vnd.github+json" },
>     payload: JSON.stringify({ ref: "main" }),
>     muteHttpExceptions: true
>   });
>   const ok = res.getResponseCode() === 204;
>   MailApp.sendEmail(Session.getActiveUser().getEmail(),
>     "【情資看板】已 " + Math.floor(hours) + " 小時未更新，" + (ok ? "已自動補跑" : "自動補跑失敗"),
>     "最後更新時間：" + data.generated + "\n" +
>     (ok ? "已觸發「情資自動更新」，約一分鐘後完成。"
>         : "GitHub 回應 " + res.getResponseCode() + "：" + res.getContentText() + "\n請手動執行或檢查權杖是否過期。") +
>     "\nhttps://github.com/allanloplus/intelligence/actions/workflows/update-intel.yml");
> }
> ```
>
> 要套用到自己的系統，只需改前三行：網站資料網址、門檻小時數、你的 repo 與 workflow 檔名。
>
> 【畫面：程式碼編輯畫面（截圖 4）】
>
> **第二步：存放權杖**
> 1. 左側**齒輪圖示**「專案設定」→ 捲到最下方「**指令碼屬性**」→ **新增指令碼屬性**
> 2. 屬性：`GITHUB_TOKEN`；值：貼上剛才複製的權杖 → **儲存指令碼屬性**
>
> 【畫面：指令碼屬性畫面（截圖 7，權杖值已遮蔽）】
>
> **第三步：手動執行一次並授權**
> 1. 回到左側 `< >` 編輯器 → 上方函式選單確認是 `checkIntelFreshness` → 按 **執行**
> 2. 第一次執行會跳出授權視窗，要求允許「連線到外部服務」與「以你的名義傳送電子郵件」→ 選擇你的帳號 → 允許
>    （依帳號類型不同，可能會多一道確認畫面）
> 3. 下方「執行記錄」顯示「執行完畢」即可。若網站在門檻時間內有更新，程式會直接結束、不寄信，這是正常的。
>
> **第四步：設定定時執行**
> 1. 左側**鬧鐘圖示**「觸發條件」→ 右下 **新增觸發條件**
> 2. 依序選擇：
>    - 選擇您要執行的功能：`checkIntelFreshness`
>    - 選取活動來源：**時間驅動**
>    - 選取時間型觸發條件類型：**小時計時器**
>    - 選取小時間隔：**每 6 小時**
>    - 錯誤通知設定：**每天通知我**
> 3. **儲存**
>
> 【畫面：編輯觸發條件畫面（截圖 5）、觸發條件列表（截圖 6）】

**Allan**【表情：驚訝】
MAX_HOURS 要去哪裡改？我在設定畫面找不到。

**阿拉蕾**【表情：疑問抓頭】
啊，它不是畫面上的設定，是**程式碼的第 2 行**。直接改數字，再按儲存就好。

**Allan**【表情：抓頭】
原來是程式碼裡的一行。妳早說嘛。

> **💡 不寫程式的人最常卡住的地方**
> AI 說「把 MAX_HOURS 改成 12」時，它腦中想的是程式碼；不寫程式的人想的是設定畫面。
> 卡住時直接問「**這個要去哪裡改？**」，請 AI 講到「哪個畫面、第幾行、按哪個按鈕」為止。

### 場景 8：要跑多頻繁才夠？

**Allan**【表情：思考】
> 「一般而言，情資的網站更新頻率最多就是一天一次。那觸發的頻率，需要為 6 小時或一天 2 次以上嗎？」

**Allan**【表情：思考】

**Allan**【表情：豎指頭】

**阿拉蕾**【表情：眨眼比讚】
收到。12 小時沒更新就補跑，Apps Script 每 6 小時看一次。

> **💡 Allan 為什麼這樣說**

### 本集一句話

> **自動化不是設好就好。**
> 你要知道它有在做、做得對，沒做時會自己補上，補不了時會叫人。
> 而「它真的在運作」這件事，要由人來確認，不能只聽 AI 說完成。

### 課後思考

1. 你現有的自動化或排程工作，如果「沒執行」，你會知道嗎？誰會通知你？
2. 你的告警規則，有沒有被實際觸發過？
3. 你的系統裡有沒有權杖或密碼？它們的範圍、效期、保管位置是什麼？
