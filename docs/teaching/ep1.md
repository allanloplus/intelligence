# 會自我檢查的自動化：用 AI 協作打造一條 PDCA 資料管線
## 以資安情資蒐集為例｜第 1 集（Plan）：交代工作，不是寫提示詞

### 場景 1：先給 AI 一個工作的地方

【畫面：Allan 坐在電腦前，螢幕是 GitHub 的「Create a new repository」頁面】

**Allan**【表情：微笑】
民國 115 年 11 月 26 日下午，我先在 GitHub 開了一個新的空 repo，叫 `intelligence`。裡面只放了一個檔案，什麼程式都沒有。

**阿拉蕾**【表情：疑問抓頭】
Repo 是什麼？聽起來好像很工程師。

**Allan**【表情：豎指頭】
妳就當它是一個**會記住每一次修改的雲端資料夾**。誰在什麼時候改了什麼，全部留紀錄。對稽核員來說，這是天生的稽核軌跡。

**阿拉蕾**【表情：平板展示】
然後您在 claude.ai/code 開了一個工作階段，把這個 repo 交給我。我在雲端的工作環境裡寫程式、測試，做好了推到一個 `claude/` 開頭的分支上。

**Allan**【表情：正經】
重點是：**妳推上來的東西，要我按下合併才會生效。** 妳可以提案，決定權在我。

**阿拉蕾**【表情：眨眼比讚】
AI 提案、人核准。這本身就是一個控制點！

> **🛠 動手做｜準備 AI 的工作環境**
> 1. **建立 GitHub 帳號與 repo**：github.com → 右上「+」→ New repository → 輸入名稱 → 勾選 Add a README file（或隨意放一個檔案）→ Create repository。
>    ※ 之後要用免費的 GitHub Pages 發佈網站，repo 請設為 **Public**；若資料不宜公開，需另外評估付費方案或其他發佈方式。
> 2. **讓 Claude 能存取 GitHub**：到 claude.ai/code，依畫面指示連結 GitHub 帳號，並在要使用的 repo 上安裝 Claude GitHub App（可只授權單一 repo）。
> 3. **開一個工作階段**：在 Claude 應用程式的 Code 分頁（或網頁版 claude.ai/code）按「**新增**」。輸入框下方的工具列由左到右是：
>    - **雲端環境**：決定 AI 的工作環境能連到哪些網站。本個案要抓四個情資網站，所以選「允許網路完整存取」。
>    - **repo**：選剛建立的 repo（本個案為 `intelligence`）。
>    - **分支**：選要從哪個分支開始，通常是 `main`。AI 不會直接改 `main`，而是另外建一個 `claude/` 開頭的分支，在上面工作。
>
>    選好之後，在「描述任務或提出問題」的輸入框用中文交代工作即可。
> 4. **AI 的成果會變成 Pull Request（PR）**：AI 在 `claude/…` 分支上工作，成果以 PR 呈現。你在 GitHub 上看過內容、按 **Merge pull request**，才會進入正式的 `main` 分支。
>
> 【畫面：開新工作階段的畫面。紅框由左到右是雲端環境、repo（intelligence）、分支（main）；上方是點開雲端環境後的選單（截圖 17）】

> **📋 ISMS 旁註｜最小授權與變更核准**
> Claude GitHub App 可以只授權單一 repo，這是最小權限原則。
> 「AI 在分支工作、人核准合併」對應變更管理：每一次變更都有申請（PR）、有審查、有核准者（合併的人），而且全部留在 GitHub 紀錄裡。

### 場景 2：Allan 的第一段話

【畫面：對話框，完整呈現 Allan 的開場訊息，字體放大】

**Allan**【表情：思考】
環境準備好之後，我跟阿拉蕾說的第一段話是這樣的：

> 「能不能建立自動化情資更新機制？不一定要依照上述模式，但 Excel 表的欄位需求是必要的（以 2026 年 11 月的為主）。也希望能保留過去 3 年的資料提供查詢及下載。請另外建立新的機制，別影響目前的 Google sheet，好多系統及好多 User 需要它，而且 12 月初快到了 User 會來網頁下載情資資料。」

前面我還交代了現況，也就是上一集講的那六個步驟。

**阿拉蕾**【表情：驚訝】
就這樣？沒有「你是一位資深工程師」、沒有特殊格式、沒有一長串規則？

**Allan**【表情：大笑】
沒有。我就是用平常交代顧問案的方式講。

**阿拉蕾**【表情：平板展示】
可是我收到的時候，覺得資訊非常完整。我把它拆給大家看：

| 要素 | Allan 說的 | 對我的意義 |
|---|---|---|
| **現況** | 六個步驟，包含哪些系統相依 | 我知道問題在哪、牽涉到什麼 |
| **目標** | 建立自動化情資更新機制 | 方向明確 |
| **放手的範圍** | 「不一定要依照上述模式」 | 我可以提出不同的架構 |
| **不能妥協的條件** | Excel 欄位（以 2026 年 11 月為準）、保留三年可查詢下載 | 驗收標準明確 |
| **不能碰的東西與原因** | 別影響現有 Google Sheet，因為很多系統、很多人在用，12 月初要下載 | 說了原因，我才能自己判斷邊界 |

> **💡 Allan 為什麼這樣說**
> 最值得學的是最後一句：**不只說「不能碰」，還說了「為什麼不能碰」。**
> 如果只說「別動 Google Sheet」，AI 只會遵守這一條。說了「好多系統及好多 User 需要它，12 月初要下載」，AI 就能自己推論：任何會影響那份 Sheet 的動作，包括寫入、改格式、改分頁名稱，都不能做；而且新系統要在 12 月初前可用。
> 交代原因，等於把判斷力一起交出去。

### 場景 3：「需要任何權限請直接跟我說」

**Allan**【表情：豎指頭】
我還加了一句：「需要任何權限請直接跟我說，我開放。」

**阿拉蕾**【表情：疑問抓頭】
這句話我很感謝，但聽起來有點危險耶？給 AI 全部的權限？

**Allan**【表情：眨眼】
妳仔細看，我說的是「**跟我說**，我開放」，不是「妳自己拿」。權限還是我給的，只是我不希望妳因為卡在權限上，就默默換一個比較差的做法。

**阿拉蕾**【表情：思考】
懂了。所以我的責任是：需要什麼權限，要先說清楚**要什麼、為什麼要、範圍多大**，讓您判斷。

**Allan**【表情：正經】
對。到第 4 集我們會遇到一個真實的例子：要建一把 GitHub 權杖。那時候範圍要怎麼開、效期要多長，就是這樣討論出來的。

### 場景 4：動手前的第一件事：只看，不碰

【畫面：阿拉蕾戴著耳機、拿著放大鏡看一份試算表，旁邊有一個大大的「唯讀」印章】

**阿拉蕾**【表情：平板展示】
收到需求後，我做的第一件事不是寫程式，而是**以唯讀方式下載現有的 Google Sheet**，確認三件事：

1. 2026 年 11 月的分頁有哪 14 個欄位、順序是什麼
2. 每個欄位的資料長什麼樣子、來自哪些情資來源
3. 過去三年的資料有多少、格式有沒有變過

**Allan**【表情：微笑】
然後妳跟我回報。

**阿拉蕾**【表情：攤手說明】
對。而且回報時我會講清楚：我**讀了**什麼，我**沒有寫入任何現有系統**。

**Allan**【表情：豎指頭】
這就是我要的。先看現況再動手，而且讓我知道妳碰了什麼、沒碰什麼。

> **💡 為什麼「先看現況」這麼重要**
> AI 很擅長「直接做出一個東西」。但如果它不知道現況，做出來的可能是一個漂亮、卻跟你的欄位、你的資料、你的使用者都對不上的系統。
> 請 AI 先盤點現況，有兩個好處：
> 1. 它的設計會建立在真實資料上，不是想像。
> 2. 你可以從它的回報檢查：**它理解的現況，跟你認知的一樣嗎？** 不一樣的話，在動手前修正最便宜。

> **📋 ISMS 旁註｜先盤點再變更**
> 唯讀盤點對應資產盤點與變更前的影響分析。
> 對稽核員來說，可以問：導入自動化之前，有沒有確認既有資料流與相依系統？有沒有證據顯示既有系統未受影響？本個案中，舊 Google Sheet 與相依系統全程沒有被修改。

### 場景 5：不懂技術，可以開始嗎？

【畫面：一位上班族學員縮在角落，頭上冒出「我又不會寫程式……」的對話框】

**阿拉蕾**【表情：握拳加油】
我想替不寫程式的朋友問一句：Allan 老師，您懂 GitHub，所以才能這樣做。一般資安承辦也可以嗎？

**Allan**【表情：思考】
我觀察到，不寫程式的人最大的障礙是**不敢開始**，以為要先懂技術。

**Allan**【表情：豎指頭】
但你剛剛看到的那段話，有任何技術名詞嗎？沒有。要懂的是**自己的業務**，還有「**什麼叫做對**」。

**阿拉蕾**【表情：眨眼比讚】
不知道怎麼做沒關係，那是我的工作。

**Allan**【表情：正經】
對。**不知道怎麼做沒關係，不知道怎麼驗收才是問題。** 如果你說不出「做對」長什麼樣子，AI 做完了你也不知道能不能用。

### 本集一句話

> **大家以為要學的是「正確的提示詞」，其實要學的是「怎麼交代工作」。**
> 用交代顧問案的方式講：現況、目標、能放手的、不能妥協的、不能碰的與原因。

### 🎒 帶得走的工具卡

**交代工作的五個問題**

1. 現在怎麼做？
2. 想變成什麼樣？
3. 哪些要保留、哪些可以改？
4. 什麼絕對不能碰？**為什麼？**
5. 怎麼知道做對了？

**跟 AI 協作的三個習慣**

1. **請 AI 先看現況再動手**，並回報它碰了什麼、沒碰什麼。
2. **每個階段都問：你驗證了什麼？沒驗證什麼？**（下一集會看到這句話有多重要）
3. **看到不對勁，直接講你觀察到的現象**，不必先下診斷。（第 4 集的主角）

### 課後思考

1. 拿一件你想自動化的工作，試著用五個問題寫一段交代。第 4 題的「為什麼」寫得出來嗎？
2. 第 5 題「怎麼知道做對了」，你能拿出一個標準答案嗎？
